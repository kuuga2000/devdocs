Nginx Troubleshooter

Follow these steps to find out why your service failed to start.

0

Create Site in sites-available

Create a new Nginx site config file, then enable it through a symlink in sites-enabled.

sudo nano /etc/nginx/sites-available/example.com
sudo ln -s /etc/nginx/sites-available/example.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

Example server block

server {
    listen 80;
    listen [::]:80;
    server_name example.com www.example.com;

    root /var/www/example.com/html;
    index index.html index.htm index.nginx-debian.html;

    access_log /var/log/nginx/example.com.access.log;
    error_log /var/log/nginx/example.com.error.log;

    location / {
        try_files $uri $uri/ =404;
    }
}

Check Config Syntax

Most failures are caused by a typo in nginx.conf or site-available files.

sudo nginx -t
Look for: "syntax is ok" and "test is successful". If it fails, it will tell you exactly which line has the error.
2

Check Port 80/443 Conflict

Check if another process (like Apache or another Nginx instance) is already using the ports.

sudo ss -tulpn | grep :80
3

Read Error Logs

If the syntax is OK, the specific error will be at the bottom of the system log.

sudo journalctl -xeu nginx.service
sudo tail -n 20 /var/log/nginx/error.log
4

Sync Config to Server

If you keep Nginx config locally in your project, sync it to the remote server and reload Nginx safely.

rsync -av ./nginx/ deploy@example.com:/etc/nginx/sites-available/
scp ./nginx/example.com deploy@example.com:/etc/nginx/sites-available/example.com
ssh deploy@example.com "sudo nginx -t && sudo systemctl reload nginx"

Common "Fail to Start" Fixes

  • •
    Missing Directories: Nginx fails if a path in access_log or root doesn't exist. Run sudo mkdir -p /path/to/dir.
  • •
    Permission Denied: Check if Nginx has access to your web root: sudo chown -R www-data:www-data /var/www/html.
  • •
    SELinux (CentOS/RHEL): If you are on CentOS, SELinux might block Nginx. Try setsebool -P httpd_can_network_connect 1.
